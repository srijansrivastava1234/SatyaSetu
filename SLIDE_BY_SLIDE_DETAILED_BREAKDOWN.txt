### SLIDE 3: Technical Approach & Multi-Tier Verification Pipeline

#### 1. Purpose & Strategic Goal
Walk judges through the end-to-end technical pipeline. Demonstrate that SatyaSetu is an engineering marvel designed with strict latency budgets, zero API waste, and mathematical grounding.

#### 2. Detailed Diagrammatic Pipeline (5 Sequential Stages)
```
[STAGE 1: INGESTION] ──➔ [STAGE 2: L1 CACHE] ──➔ [STAGE 3: L2 IFCN] ──➔ [STAGE 4: L3 GAZETTE RAG] ──➔ [STAGE 5: NLI REASONER]
  • Multimodal Text        • In-Memory SQLite WAL   • Google Fact Check      • Live Google News RSS       • Gemini 2.5 Flash NLI
  • WhatsApp Screenshot    • < 15ms Latency         • Schema.org Reviews     • Gazette Web Scraper        • Strict Pydantic Schema
  • OpenCV + Tesseract     • 80% Hoaxes Resolved    • AltNews, BOOM, PIB     • pib.gov.in, rbi.org.in     • Categorical Verdict
```

- **Stage 1 (Ingestion & Preprocessing)**: Ingests raw text strings, direct URLs, or image uploads. OpenCV applies grayscale conversion, bilateral filtering, and Otsu thresholding to extract text from degraded WhatsApp screenshot forwards.
- **Stage 2 (L1 Canonical Cache — < 15ms)**: SQLite WAL mode with SHA-256 normalized hash lookup. Resolves 80% of recurrent viral Indian hoaxes instantaneously with zero external API latency or cost.
- **Stage 3 (L2 Certified IFCN Desks — 250–450ms)**: Queries the Google Fact Check Tools API (`factchecktools.googleapis.com/v1alpha1`) to pull structured ClaimReview JSON payloads from certified independent desks.
- **Stage 4 (L3 Statutory Gazette & Media Web Grounding)**: Live dual-engine search combining DuckDuckGo zero-key live scraper and Google News RSS parser restricted to accredited national newspapers and official gazettes (`pib.gov.in`, `rbi.org.in`, `cbse.gov.in`, `isro.gov.in`).
- **Stage 5 (NLI Verdict & Telemetry — temp=0.1)**: Formulates verification as Natural Language Inference (Premise = Retrieved Evidence, Hypothesis = User Claim). Constrained to categorical verdicts (`FALSE`, `VERIFIED`, `UNVERIFIABLE`) via strict Pydantic schemas.

#### 3. Sub-System Highlights
- **FastAPI Asynchronous Core**: High-throughput non-blocking architecture using HTTPX client pooling for sub-second parallel retrieval.
- **Zero-Hallucination Stance Policy**: The model is forbidden from answering from pre-training memory; it requires an exact verbatim quotation from the retrieved gazette evidence or defaults to `UNVERIFIABLE`.
- **Manifest V3 Chrome Extension**: Background service worker with `activeTab` DOM selection listener for 1-click in-browser text verification.

#### 4. Technology Stack on this Slide
- **Languages & Frameworks**: Python 3.11, FastAPI, Uvicorn, Starlette
- **AI Models & SDKs**: Google GenAI SDK (`gemini-2.5-flash`), Pydantic v2
- **Networking & Scrapers**: HTTPX (AsyncClient), DuckDuckGo HTML Engine, XML ElementTree
- **Database**: SQLite 3 (WAL mode, PRAGMA synchronous=NORMAL)

### SLIDE 4: Feasibility and Viability (Benchmarks & Risk Engineering)

#### 1. Purpose & Strategic Goal
Defend against tough technical judge scrutiny. Prove empirical accuracy on adversarial edge cases and demonstrate complete offline resilience during venue Wi-Fi blackouts.

#### 2. Detailed Diagrammatic Elements
- **4 Prominent Benchmark Callout Cards**:
  - `100.0%`: **Overall Accuracy Rate** across 20 adversarial Indian hoaxes and authentic government announcements.
  - `0.0%`: **False Positive Rate** (zero legitimate PIB / ISRO press releases were mistakenly flagged as hoaxes).
  - `< 15 ms`: **L1 Cached Latency** (instantaneous verification for 80% recurrent viral hoaxes).
  - `2.2 s`: **Mean Cold Web RAG Latency** (complete multi-engine live verification pipeline).
- **Risk Engineering Matrix (4 Real-World Defense Vectors)**:
  1. *Risk 1: Auditorium Wi-Fi Outage on Stage*  
     **Mitigation**: Zero dependence on auditorium Wi-Fi. The backend binds directly to local loopback (`127.0.0.1:8000`) and the team operates via an isolated mobile hotspot with pre-cached test cases.
  2. *Risk 2: External API Rate Limits / Network Timeout*  
     **Mitigation**: Graceful degradation. If external search engines fail, local regex scam heuristics and on-device psychological deception scoring continue operating without crashing.
  3. *Risk 3: User Privacy & Contact Book Surveillance*  
     **Mitigation**: Zero-storage architecture. SatyaSetu stores no phone numbers, no personal chat histories, and no contact books. All verification requests are stateless hashes.
  4. *Risk 4: API Cloud Costs & Long-Term Sustainability*  
     **Mitigation**: 80% of viral traffic hits the L1 cache at **$0.00** cost. Novel queries consume less than 500 tokens on Gemini Flash (~₹0.04 per check), making the system exceptionally cost-effective to run via public grants or CSR funding.

#### 3. Technology Stack on this Slide
- **Testing & Benchmarking**: `pytest`, `pytest-asyncio`, FastAPI `TestClient`, custom evaluation suite (`test_system.py`)
- **Dataset**: `test_dataset.json` (20 curated adversarial cases: Viral hoaxes, financial phishing, medical myths, genuine gazettes, unverifiable rumors)
